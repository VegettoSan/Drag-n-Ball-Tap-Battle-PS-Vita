# Runtime Data and Mod Layout

## Base path

```text
ux0:data/DBTapBattle/
```

The VPK should contain only the native executable and port-owned resources. Original game content is installed separately.

## Original game

```text
ux0:data/DBTapBattle/game/
```

This directory mirrors the useful original APK data as closely as possible. For the supplied APK, the initial extractor copies files from `res/raw/` here, preserving filenames such as:

```text
back00.pac
back01.pac
common.pac
effect.pac
font00.pac
gamedata.pac
select0.pac
text00.pac
bgm_00.ogg
se_00.ogg
loading.png
mk.bin
...
```

The exact manifest is generated by `tools/extract_apk_data.py` rather than hardcoded into the port.

## Mods

Each first-level directory inside `mods/` is one selectable mod:

```text
ux0:data/DBTapBattle/mods/
├── FighterZ/
│   ├── mod.json
│   ├── select0.pac
│   ├── char05.pac
│   └── char08.pac
└── AnotherMod/
    ├── mod.json
    └── effect.pac
```

A mod is not required to duplicate the entire game.

## Virtual file resolution

For a request such as `select0.pac` with mod `FighterZ` active:

```text
1. ux0:data/DBTapBattle/mods/FighterZ/select0.pac
2. ux0:data/DBTapBattle/game/select0.pac
3. Missing-resource error
```

With `Original` selected, only the `game/` path is considered.

Nested relative paths use the same rule.

## Optional mod metadata

`mod.json` is port-owned metadata and does not modify original Tap Battle formats.

Recommended schema:

```json
{
  "name": "Dragon Ball FighterZ Mod",
  "author": "Author",
  "version": "1.0",
  "description": "Optional description"
}
```

Current implementation uses the directory name; mod.json parsing is PENDING.
The diagnostic font is ASCII-only; paths retain UTF-8 bytes.

## Safety rules

- Never write mod files into `game/`.
- Never patch original PAC files in place during normal play.
- Save/configuration data should live outside both `game/` and individual mod resource folders.
- Path traversal such as `../` must not be accepted by the virtual filesystem.

## Writable paths and completeness

Current bootstrap creates config/, logs/, saves/ alongside game/ and mods/.
Log: ux0:data/DBTapBattle/logs/runtime.log. Original data presence currently
means game/common.pac is a regular file, independent of an active mod; it is
not a complete installation test. Original charNN/chardemoNN/charf00NN triplets
are absent in the supplied APK. Runtime save files remain PENDING.

## Community assets as a separate dataset

`extract_apk_data.py community.apk ./install --mod Android14` prepares
install/mods/Android14/, with canonical names and untouched encoded PACs.
Copy under ux0:data/DBTapBattle/mods/Android14/. Format-3 import manifest records
profile, alias mapping and original APK content hashes. Native codec detection
is per PAC, not globally per active mod. The original game/ folder and missing
resource fallback remain unchanged. See ANDROID14_APK.md for the exact profile
and resource/engine compatibility boundary.
